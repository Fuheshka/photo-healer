**Инструмент форензики, скоростной экспертизы и трансплантации заголовков для фотоархивов, пострадавших от SSD TRIM и быстрого форматирования.**

Когда на твердотельном накопителе (SSD) удаляется раздел или выполняется быстрое форматирование, контроллер диска запускает команду TRIM (Deallocate). Физические секторы, выделенные под удаленные файлы, моментально зануляются. Программы восстановления данных (Recuva, DMDE, R-Studio, PhotoRec) легко находят структуру папок и имена файлов по уцелевшим записям MFT/FAT, однако сами файлы не открываются или отображаются черным квадратом: первые 32-64 КБ файла, где хранится служебный заголовок JPEG, занулены.

При этом **энтропийный поток данных** (реальные коэффициенты DCT и закодированные Хаффманом пиксели снимка) расположен в следующих кластерах диска и часто остается целым. **Photo Healer** проводит потоковый анализ повреждений, определяет наличие живых данных, пересаживает заголовок от целой донорской фотографии с такой же камеры, восстанавливает сдвинутые цветовые блоки (MCU resync) и извлекает встроенные миниатюры высокого разрешения.

## Ключевые возможности

- **Потоковая O(1) экспертиза (Triage):** Чтение файлов порциями по 64 КБ без загрузки всего файла в оперативную память. Мгновенная сортировка архива на целые файлы, 100% пустышки TRIM, пригодные к починке кандидаты и неизвестные форматы.
- **Трансплантация донорского заголовка:** Извлечение структуры заголовка (`SOI` -> `Exif` -> `DQT` -> `SOF0` -> `DHT` -> `SOS`) из подходящего донора и сшивание с уцелевшим энтропийным потоком.
- **Ресинхронизация потока MCU:** Обнаружение поврежденных маркеров перезапуска (`RST0`-`RST7`) и выравнивание геометрии (`pad_geometry`), устраняющее сдвиг строк и фиолетово-зеленые полосы на восстановленном снимке.
- **Карвинг встроенных превью (Carve):** Извлечение неповрежденных миниатюр (`APP1 EXIF`, `APP2 MPF Full HD` и потоков JPEG) даже в случаях, когда исходный полноразмерный кадр пострадал слишком сильно.
- **Графический интерфейс на PySide6:**
  - **Таблица экспертизы:** Виртуализированный список на 50 000+ файлов с фильтрами по статусам и цветными бейджами.
  - **Сплит-просмотр со слайдером:** Наглядное сравнение «до и после» с интерактивным разделителем, синхронным зумом и перемещением, а также диагностическими карточками качества.
  - **Галерея превью (Carve View):** Адаптивная сетка найденных миниатюр с бейджами разрешения и пакетным экспортом в выбранную папку.
- **Автономный модуль проверки обновлений:** Проверка релизов через GitHub Releases API без сторонних сетевых библиотек с защитой от превышения лимитов запросов (раз в 24 часа).
- **Скрипты без зависимостей:** Автономный сценарий `triage.ps1` для Windows на PowerShell 5.1+ (работает прямо из коробки без установки Python), а также отдельные скрипты `triage.py`, `heal.py` и `quarantine.py`.

## В чем суть проблемы SSD TRIM

| Симптом | Причина | Можно восстановить? |
|---|---|---|
| Файл не открывается / «Ошибка формата» | Первые 128 секторов (65 536 байт) занулены TRIM | **Да** - трансплантация донорского заголовка |
| Файл состоит из одних нулей (100% 0x00) | Контроллер SSD занулил файл целиком | **Нет** - TRIM-пустышка, отправляется в карантин |
| Снимок сдвинут по горизонтали, фиолетовые блоки | Повреждены маркеры перезапуска в энтропийном потоке | **Да** - ресинхронизация потока MCU |
| Полноразмерный кадр битый, но превью целое | Зануление затронуло тело кадра, но обошло блок метаданных | **Да** - извлечение превью APP1/APP2 через карвер |

```
Структура стандартного файла JPEG:
[SOI FF D8] → [APP0/APP1 Exif] → [DQT таблицы квантования] → [SOF0 параметры кадра]
→ [DHT таблицы Хаффмана] → [SOS заголовок сканирования] → <энтропийный поток пикселей> → [EOI FF D9]

Профиль повреждений SSD TRIM:
[00 00 00 ... 00 00 00] (первые ~64 КБ стерты) → <живые энтропийные данные сохранились!>
```

## Быстрый старт

### Установка

Установка пакета с графическим интерфейсом:
```bash
pip install -e ".[gui]"
```

Установка с инструментами для тестирования и разработки:
```bash
pip install -e ".[dev,gui]"
```

### 1. Запуск графического интерфейса (GUI)

Запустите графическое приложение одной из команд:
```bash
photo-healer gui
# или напрямую через точку входа
photo-healer-gui
```

### 2. Использование командной строки (CLI)

#### Экспертиза и сканирование архива (Triage)
```bash
# Проанализировать каталог с фотографиями и сохранить отчет в JSON
photo-healer triage "D:\RecoveredPhotos" --report report.json

# Проанализировать каталог и переместить 100% TRIM-пустышки в отдельную папку
photo-healer triage "D:\RecoveredPhotos" --quarantine "D:\TRIM_Quarantine"
```

#### Восстановление поврежденных фотографий (Heal)
```bash
# Восстановить кандидатов из отчета с сохранением результата в отдельную папку
photo-healer heal --candidates report.json --output "D:\HealedPhotos"

# Восстановление на месте с созданием резервных копий .bak
photo-healer heal --candidates report.json --inplace

# Пакетное автовосстановление: автоматический подбор доноров из той же папки
photo-healer batch-heal "D:\RecoveredPhotos" --out-dir "D:\HealedPhotos"
```

#### Извлечение скрытых миниатюр и превью (Carve)
```bash
# Извлечь встроенные превью EXIF и MPF из поврежденных или пустых файлов
photo-healer carve "D:\RecoveredPhotos" --out-dir "D:\ExtractedPreviews"
```

#### Проверка наличия обновлений
```bash
# Проверить актуальную версию на GitHub
photo-healer update-check
```

### 3. Автономные скрипты без установки окружения

Для полевой работы на компьютерах без настроенного Python-окружения:
```powershell
# PowerShell 5.1+ (встроен в Windows 10/11 по умолчанию)
.\triage.ps1 -Root "D:\RecoveredPhotos" -Quarantine "D:\TRIM_Quarantine"
```

```bash
# Прямой запуск автономных скриптов Python
python triage.py "D:\RecoveredPhotos" --report report.json
python heal.py --candidates heal_candidates.json --inplace
python quarantine.py --report report.json --target "D:\TRIM_Quarantine"
```

## Архитектура проекта

```
photo-healer/
├── src/photo_healer/
│   ├── core/                  # Алгоритмы форензики (без внешних зависимостей)
│   │   ├── carver.py          # Извлечение превью APP1/APP2 и потоков JPEG
│   │   ├── entropy.py         # Расчет энтропии Шеннона и анализ распределения
│   │   ├── parser.py          # Парсер маркеров и сегментов JPEG (SOI..SOS)
│   │   ├── resync.py          # Выравнивание маркеров перезапуска MCU
│   │   ├── splicer.py         # Синтез и сшивание донорского заголовка
│   │   └── validator.py       # Структурный валидатор формата JPEG
│   ├── cli/                   # Интерфейс командной строки
│   │   ├── main.py            # Точка входа CLI (triage, heal, carve и др.)
│   │   ├── banner.py          # Моноширинные карточки и баннеры в терминале
│   │   ├── i18n.py            # Двуязычная локализация CLI (RU / EN)
│   │   └── updater.py         # Проверка обновлений через GitHub Releases
│   └── gui/                   # Графический интерфейс на PySide6
│       ├── app.py             # Точка входа и инициализация Qt
│       ├── i18n.py            # Реактивное переключение языков на лету
│       ├── models/            # Виртуализированная табличная модель и фильтры
│       ├── views/             # Экраны экспертизы, восстановления и карвинга
│       ├── widgets/           # Сплит-просмотр со слайдером и зумом
│       └── workers/           # Фоновые потоки QThread без зависания UI
├── tests/                     # 396+ автоматических тестов pytest
├── triage.ps1                 # Автономный сканер для PowerShell
├── triage.py                  # Автономный скрипт первичной экспертизы
├── heal.py                    # Автономный скрипт трансплантации заголовков
└── quarantine.py              # Автономный скрипт изоляции пустых файлов
```

## Результаты на реальном архиве

Проверено на семейном фотоархиве объемом 4.45 ГБ, восстановленном после форматирования SSD:

```
[TRIM]  trim_zero            2345 файлов   4 315.7 МБ  (полные нули, восстановить невозможно)
[HEAL]  healed_candidate        7 файлов      20.1 МБ  (100% файлов успешно восстановлено)
[OK]    valid                  33 файла      115.8 МБ  (целые фотографии, использованы как доноры)
```

Все 7 поврежденных файлов были восстановлены в исходном разрешении 3264×2448 px (камера SANYO Xacti E6 8 MP). Изображения визуально безупречны и декодируются любыми стандартными просмотрщиками.
